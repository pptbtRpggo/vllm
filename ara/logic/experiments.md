# 建议的后续实验流程

Provenance：ai-suggested。这些是后续方案，并未在本次复盘中执行新NPU实验。

| 阶段 | 要回答的问题 | 放行条件 |
|---|---|---|
| 0. 评价合同与协议diff | 要验证效率、业务SLO还是硬件等效？ | 指标、门槛、覆盖、负载和版本字段明确；测试/调参职责分开 |
| 1. 原生/零等待/等待小实验 | 测量和模拟是否会改变所测系统？ | 预先定义容差；独立计时核对；对应phase、模式、同计算量 |
| 2. 少量代表负载 | 哪些负载最可能让模拟或模型失效？ | 低/高并发、短/长输入及端点stage都检查；形状和阶段单列 |
| 3. DP预测与候选serving | 输入成本能否解释候选排序？ | 枚举验证DP；推荐、均分及预先列出的邻近候选留出比较 |
| 4. 独立SLO校准 | 同正式协议下门槛怎样选？ | 校准集决定门槛；验证前冻结；验证不通过也保留，不偷偷抬门槛 |
| 5. 配对正式测量 | 新方法在限定场景中有何收益？ | 三策略同输入ID/token顺序、warmup与输出；运行失败如实记录 |
| 6. 可复算交付 | 图、表和结论能否由原始记录重现？ | 数据身份/输出/元数据/SHA、图表字段及下载包CRC均通过 |

出现反常结果时优先回到最早失败的阶段，不继续堆积更多正式测量。新机制若未通过模拟精度关口，仍可研究其软件延迟场景，但应独立命名与限定结论范围。
